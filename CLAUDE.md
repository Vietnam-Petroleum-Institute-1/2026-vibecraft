# CLAUDE.md

This file provides guidance to Claude Code when working with code in this repository.

## What this repository is

This is **VibeCraft itself** — the tool being built, not a project generated by it. It will eventually be cloned/installed by end users into their own projects and run via `./scripts/init.sh`. Everything under `templates/` is the *source material* `init.sh` copies from — it is not example code to "clean up," it is the product.

This repo is built according to the phased plan in the sibling planning repo: `../plans/00-MASTER-PLAN.md` (and `../plans/0N-*.md` per phase). Read the current phase's plan file before making changes here — it documents what's already decided, what's tested, and what's intentionally deferred. Update the relevant plan file's "Tiến độ và kết quả" section after any change here, don't let this repo and the plans drift apart.

## Do not touch

- `../vibe-coding-ai-rules-main/` — the reference base repo, sibling directory. Read/copy from it, never edit it.
- `docs/` in this repo — copied verbatim from the base repo. It is **reference material only**, used when writing `templates/rules/*.md` — it is no longer copied into projects `init.sh` generates (see `../vibecraft-docs/00-PROJECT-OVERVIEW.md` §2). Extend via new files, don't rewrite existing ones.
- `AGENTS.md` at this root — a leftover reference copy of the base template (unfilled placeholders). Not this repo's active guidance file; this `CLAUDE.md` is. (The old `templates/agents/AGENTS.base.md`/`AGENTS.<framework>.md`/`AGENTS.fe.md` files it once fed have been deleted — see Structure below, superseded by `templates/rules/`.)

## Non-negotiable rules carried over into every generated project

These are enforced via the `templates/rules/*.md` content (assembled into `AGENTS.md`), not just described here:

- MVC chain: `Controller/Router → Service → Repository → Model`. No layer-skipping. Repository files live inside `modules/[feature]/`, not a shared top-level `repositories/` (NestJS, Express, and FastAPI all follow this).
- 4 project types: `app-fullstack`, `app-be-only`, `app-fe-only`, `tool-script` — `app-fe-only` never gets a `backend/`.
- No open version ranges (`^`/`~`) on main dependencies in any template — pin exact versions, verified by actually running the tool (eslint/tsc/ruff/black/mypy/actionlint), not just checking JSON/YAML syntax.
- GitHub Actions are pinned to a commit SHA looked up via the GitHub API, with the version tag in a trailing comment — never `@main`/`@master`/guessed SHAs.
- Git hooks (`.husky/`) always live at the project root, never nested inside `backend/`/`frontend/` — this applies to every project type, not just fullstack.
- "Skill" (`SKILL.md`) is a cross-tool open standard now, not Claude-Code-only — see `templates/skills/` above. Any new skill must declare `applies_to` in its own front-matter (reusing `section_applies()`'s values, extended here with `fastapi` and `react`) rather than being hardcoded into `generate_skills()`.
- `init.sh` never silently overwrites an existing directory's content. `check_existing_files()` runs first thing in `main()`, before any question is asked: if the target already has any of VibeCraft's own top-level output paths (`AGENTS.md`, `backend/`, `frontend/`, `.github/`, `.husky/`, `package.json`, ...), it aborts unless the user confirms `y` (interactive) or passed `--force` (flag/CI mode). `symlink-setup.sh`'s own overwrite-on-rerun behavior for AI-config fan-out (`AGENTS.md` → `.cursorrules`/`.claude/rules/*`/...) is intentionally exempt — that resync is the documented, expected way to re-run it.

## Testing convention for this repo specifically

Every template file added here must be exercised for real before being considered done: write a throwaway sample in a scratch directory outside version control (this repo has none right now — see `plans/01-repo-scaffold.md`), run the actual tool against it (lint, compile, `pre-commit run`, `actionlint`, a real `git commit`), then delete the scratch directory. Syntax-only validation (e.g. `JSON.parse`) is a floor, not the finish line — several real bugs in this repo (a mismatched `tsconfig.json` for Vite, a deprecated Husky hook format, a fabricated GitHub Actions SHA) were only caught this way.
